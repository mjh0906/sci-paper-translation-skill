# SCI论文中英翻译

## 核心目标

将中文学术内容转换为准确、清晰、紧凑且可投稿的技术英文。优先保证语义完整、技术关系准确和术语一致，再优化句法与篇幅。不得把语言润色变成内容改写。

## 执行流程

### 1. 建立原义清单

翻译前逐项识别并保留：研究对象、问题、方法、机制、输入、输出、约束、步骤顺序、因果关系、比较关系、参数、阈值、结论强度和适用范围。

不得因压缩而删除方法阶段、技术组件、限定条件或验证目标。若中文正文、公式、图示或图题不一致，单独指出；不得静默选择其中一个版本。

### 2. 固定术语

优先采用用户已经确认的译法，并在全文保持一致。不要为追求词汇变化而替换同一技术概念。

收到用户提供的术语表、图中英文或期刊固定译法时，将其作为本次任务的术语基线。若图中英文或图题被指定为不可修改，正文首次出现时建立对应关系，后文沿用图中标签。

### 3. 重组句子而非逐词直译

先确定每句主旨，再安排条件、原因、位置和目的。尽量把主要主语与核心动作放在句首。

将包含多个独立技术动作的中文长句拆开。每个英文句子原则上只承载一个主旨和最多一个紧密相关的补充动作。简洁化时删除重复措辞，不删除技术信息，也不要把短句重新合并成长难句。

### 4. 选择时态与语态

- 描述论文方法、模型结构、公式含义和图表内容：使用一般现在时。
- 描述已经完成的实验操作：通常使用一般过去时。
- 概括当前论文的实验结果：通常使用一般现在时，如 `The results show ...`。
- 模型、模块或算法是明确执行者时：优先使用主动语态，如 `GATv2 refines the graph topology.`
- 处理对象或结果是信息焦点时：使用被动语态，如 `The attention scores are normalized using Softmax.`
- 提出研究贡献时：允许使用 `We propose ...`，但不要让每句都以 `We` 开头。

处理中文“通过、利用、采用、引入、结合”时，根据逻辑关系选择表达：

- 机制：`through + 名词短语`
- 动作：`by + 动名词`
- 工具或模型：`using + 工具`
- 明确执行者：直接采用主动语态

避免悬垂结构。不要写 `By using GATv2, the graph topology is refined.`；改写为 `GATv2 refines the graph topology.` 或 `The graph topology is refined using GATv2.`

### 5. 形成SCI式段落

按照“问题—技术矛盾—解决方案—处理流程—输出作用”或源文真实逻辑组织段落。使用必要的 `whereas`、`therefore`、`first`、`second` 和 `finally` 显化关系，但避免每句都添加程式化过渡语。

减少连续被动结构、空泛总结和重复的 `This design/process/procedure ...`。让模型或模块直接承担动作，但不要将未经实验支持的效果改写为确定事实。

### 6. 完成语言审校

最终输出前必须读取并执行 [技术英语检查清单](references/technical-english-checklist-zh.md)。重点检查：

- 冠词和单复数；
- 超长句及一个句子中的多重主旨；
- 主要信息是否被目的、条件或地点压在句尾；
- `which/that` 的先行词是否明确；
- `respectively` 是否必要且位置正确；
- `in this paper` 与 `in this study` 是否混用或过度使用；
- 数字、公式、图表编号和变量格式；
- `such as` 与 `etc.` 是否重复；
- 冗余名词、口语化连接和无依据的 `obviously`；
- 固定术语、图中文字、表格字段与正文是否一致。

## 输出要求

- 用户只要求翻译时，直接给出可替换的英文，不附加无关解释。
- 用户要求评价或对照时，将原文、译文、修改理由分开呈现。
- 用户要求公式保持不变时，不重复翻译公式，只翻译公式引导句和变量说明。
- 用户要求简洁时，以语义完整为硬约束；默认仅压缩重复表达，不降低方法可复现性。
- 用户要求保持图和图题时，不修改图中文字或图题；通过正文定义和术语映射解决一致性问题。
- 目标期刊已有作者指南时，以期刊指南为最高格式依据。
